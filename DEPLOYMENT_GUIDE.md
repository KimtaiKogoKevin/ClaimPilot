# Complete Deployment Guide - Localhost & Replit

## Overview

This comprehensive claims management system supports dual deployment modes with complete feature parity between localhost development and Replit cloud hosting.

## System Features

### ✅ Core Functionality
- **Multi-role Authentication**: Insured, Insurer, Broker, Service Provider
- **Comprehensive Claim Forms**: Individual/Corporate claim support
- **AI-Powered Damage Assessment**: Roboflow Computer Vision integration
- **360° Video Analysis**: Complete vehicle coverage validation
- **PDF Generation**: Professional claim reports with AI analysis
- **Email Integration**: Forgot password and notifications
- **Database Management**: PostgreSQL with automated migrations
- **File Upload**: Secure cloud storage for photos and documents

### ✅ Technical Stack
- **Frontend**: React + TypeScript + Tailwind CSS + shadcn/ui
- **Backend**: Express.js + TypeScript + Drizzle ORM
- **Database**: PostgreSQL (Neon for Replit, local for development)
- **Authentication**: JWT (localhost) + Replit Auth (cloud)
- **Storage**: Local filesystem or Google Cloud Storage
- **AI Integration**: Roboflow Computer Vision API

## 🏠 Localhost Development Setup

### Prerequisites

1. **Node.js 18+** and **npm**
2. **PostgreSQL** database running locally
3. **Git** for version control

### Step 1: Project Setup

```bash
# Clone the repository
git clone <repository-url>
cd claims-management-system

# Install dependencies
npm install

# Create environment file
cp .env.example .env
```

### Step 2: Database Configuration

1. **Start PostgreSQL** service:
   ```bash
   # Ubuntu/Debian
   sudo service postgresql start
   
   # macOS with Homebrew
   brew services start postgresql
   
   # Windows
   # Start PostgreSQL service from Services panel
   ```

2. **Create database**:
   ```sql
   CREATE DATABASE claims_management;
   CREATE USER claims_user WITH PASSWORD 'your_password';
   GRANT ALL PRIVILEGES ON DATABASE claims_management TO claims_user;
   ```

3. **Update .env file**:
   ```env
   DATABASE_URL="postgresql://claims_user:your_password@localhost:5432/claims_management"
   NODE_ENV=development
   JWT_SECRET=your-super-secure-jwt-secret-key-here
   
   # Email Configuration (optional - for testing)
   EMAIL_HOST=sandbox.smtp.mailtrap.io
   EMAIL_PORT=587
   EMAIL_USER=your_mailtrap_user
   EMAIL_PASS=your_mailtrap_password
   
   # AI Integration (optional)
   ROBOFLOW_API_KEY=your_roboflow_api_key
   ROBOFLOW_MODEL_ENDPOINT=https://detect.roboflow.com/vehicle-damage-v1/1
   ```

### Step 3: Database Migration

```bash
# Push schema to database
npm run db:push

# If you get data loss warnings, force push
npm run db:push --force
```

### Step 4: Start Development Server

```bash
# Start the application
npm run dev
```

The application will be available at: **http://localhost:5000**

### Step 5: Initial User Setup

1. **Register a new account** at `/auth`
2. **Choose your role**: Insured, Insurer, Broker, or Service Provider
3. **Complete profile setup**
4. **Start creating claims**

## ☁️ Replit Deployment

### Step 1: Replit Setup

1. **Fork/Import** the project to Replit
2. **Enable the following services**:
   - PostgreSQL Database (automatically provisioned)
   - Object Storage (for file uploads)

### Step 2: Environment Configuration

Go to **Secrets** tab and add:

```env
# Database (automatically provided by Replit)
DATABASE_URL=<auto-generated-by-replit>

# Authentication
JWT_SECRET=your-super-secure-jwt-secret-key-here

# Email Service (optional)
EMAIL_HOST=sandbox.smtp.mailtrap.io
EMAIL_PORT=587
EMAIL_USER=your_mailtrap_user
EMAIL_PASS=your_mailtrap_password

# AI Integration (optional)
ROBOFLOW_API_KEY=your_roboflow_api_key
ROBOFLOW_MODEL_ENDPOINT=https://detect.roboflow.com/vehicle-damage-v1/1
```

### Step 3: Database Setup

1. **The database is automatically provisioned**
2. **Run schema migration**:
   - Open the Shell tab
   - Run: `npm run db:push --force`

### Step 4: Object Storage Setup

1. **Go to Object Storage tab** in Replit
2. **Create a bucket** (if not already created)
3. **Note the environment variables** (automatically set):
   - `PUBLIC_OBJECT_SEARCH_PATHS`
   - `PRIVATE_OBJECT_DIR`

### Step 5: Deploy

1. **Click "Run"** or use the "Start application" workflow
2. **Application deploys automatically**
3. **Access via** your Replit URL: `https://your-repl-name.your-username.repl.co`

## 🔧 Configuration Details

### Authentication Modes

#### Localhost (JWT-based)
- **Registration**: Email + password
- **Login**: Email + password  
- **Security**: JWT tokens with bcrypt password hashing
- **Sessions**: Local memory store

#### Replit (OIDC-based)
- **Registration**: Replit account integration
- **Login**: Automatic via Replit authentication
- **Security**: OpenID Connect with Replit as provider
- **Sessions**: PostgreSQL session store

### File Storage Options

#### Localhost
```javascript
// Local filesystem storage
const uploadPath = './uploads';
// Files stored in: ./uploads/claims/[claimId]/[filename]
```

#### Replit
```javascript
// Google Cloud Storage via Replit Object Storage
const bucketName = process.env.BUCKET_NAME;
// Files stored in: gs://bucket/private/uploads/[claimId]/[filename]
```

### Database Differences

#### Localhost
- **Driver**: `pg` (standard PostgreSQL driver)
- **Connection**: Direct TCP connection
- **Migrations**: `npm run db:push`

#### Replit  
- **Driver**: `@neondatabase/serverless` (WebSocket-compatible)
- **Connection**: Serverless connection via Neon
- **Migrations**: Same commands work automatically

## 🚀 Production Considerations

### Security Hardening

#### Environment Variables
```env
# Use strong secrets in production
JWT_SECRET=<64-character-random-string>
DATABASE_URL=<production-database-url>
NODE_ENV=production
```

#### HTTPS Configuration
- Replit: **Automatic HTTPS** provided
- Localhost: Use **reverse proxy** (nginx/Apache) for HTTPS

### Performance Optimization

#### Database
- **Connection pooling**: Enabled by default
- **Query optimization**: Indexed common queries
- **Migration strategy**: Use `db:push --force` for schema updates

#### File Storage
- **CDN integration**: Recommend for large deployments
- **Compression**: Images automatically optimized
- **Cleanup**: Automatic cleanup of abandoned uploads

### Monitoring & Logging

#### Application Logs
```bash
# Localhost
npm run dev 2>&1 | tee application.log

# Replit  
# Logs available in the Console tab
```

#### Database Monitoring
- **Connection count**: Monitor active connections
- **Query performance**: Use `EXPLAIN ANALYZE` for slow queries
- **Storage usage**: Monitor database size growth
